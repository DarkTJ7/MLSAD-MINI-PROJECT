# Using a peer agent design as a reference

The [Vocod3r motor-insurance repository](https://github.com/Vocod3r/MLSD_Project_Team1) addresses the same course brief. We studied its [agent roles and prompts](https://github.com/Vocod3r/MLSD_Project_Team1/blob/main/app/agents.py), [architecture](https://github.com/Vocod3r/MLSD_Project_Team1/blob/main/docs/ARCHITECTURE.md) and [evaluation guide](https://github.com/Vocod3r/MLSD_Project_Team1/blob/main/docs/EVALUATION.md) as examples of how to expose a policy investigation: interpret an FNOL, search apparent cover, seek a modifying clause and verify the cited answer. We did not copy its code, corpus, scenarios or claimed results.

Our implementation makes different choices:

| Design question | Peer reference | MLSAD MINI PROJECT |
| --- | --- | --- |
| Narrative interpretation | A broad triage prompt classifies the claim and extracts several entities. | A narrow local-model audit looks only for vehicle use in the incident narrative. A commercial-use signal must include an exact phrase from the claimant's text. Deterministic checks remain in force. |
| Policy evidence | The agent file includes a small stand-in corpus and clause cross-references. | An index job extracts the selected insurer PDF into page-linked chunks and a FAISS index. The model writes queries and selects retrieved clause IDs. Exact citations resolve back to the indexed PDF text. |
| Agent separation | Triage, coverage and verifier roles appear in its graph. | Research and independent verification run as separate Redis/RQ worker processes. The narrow intake audit is a stage of the research worker, not presented as a third independent agent. |
| Final answer | A model-authored coverage position passes through a verifier. | Coverage wording and routing are constrained by rules; a separate verifier checks canonical citations, expected route and semantic support. A handler still decides the claim. |
| Main interaction | FastAPI and a web client are part of the peer design. | A guided terminal agent shows live actions and verifier handoff; the simple web client remains to satisfy brief A8. |

The useful idea we adapted is the **fact-to-modifier transition**. A structured `vehicle_use=personal` can conflict with the claimant's description. For the synthetic paraphrase “taking a customer's takeaway meal to their address for a fee,” our earlier phrase rules found no restricted-use signal. The new intake audit quoted that phrase, flagged the conflict, and required private-car use restriction evidence before completion. In the final observed run, the model made a separate search for private-car use limitations, inspected a clause and handed the evidence to the verifier. The independent verifier accepted an own-damage, coverage-concern, investigation recommendation with cited cover, restriction and procedure passages. The model also made one mistaken request-fields call with a query string before correcting course; the trace keeps that call visible. Raw model decisions, citations and step timing are in [the live trace](../results/clean_agent_live.json); the synthetic input is [here](../examples/paraphrased_delivery.json).

This is one successful local-model case, not an accuracy estimate. Earlier attempts escalated after a model-purpose safety flag and after premature voluntary abstention; [the guardrail attempt](../results/narrative_audit_guardrail_failure.json) and [the early-escalation attempt](../results/narrative_audit_early_escalation_failure.json) are preserved. The frozen 24-scenario v5 comparison and container performance experiments remain pending. An incorrect audit signal cannot by itself approve or reject a claim, and an unquoted commercial-use signal is discarded. The current local classifier can still miss other unfamiliar wording; the report and requirement map keep that limitation visible.
